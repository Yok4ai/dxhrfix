# Changelog

All versions target the Steam build of `DXHRDC.exe` with sha256 `8266b6b4a5bf25f2f4e8de068aa3720f6289c962bb1c2bb70a7b1c111ba510a1`.

## 0.4.0 (2026-10-11)

First public release.

- Cursor call dedupe (`cursor_fix=1`, `cursor_refresh_ms`). The game's UI update calls `ShowCursor` in a loop and `SetCursor` / `ClipCursor` every frame, and its "show" loop raises the cursor display counter by one per visible frame. Under Wine every call is a wineserver round trip; a profiled 113 ms gameplay frame spent 78% of its time in `ShowCursor`. Import table hooks (slots verified first) keep a shadow display count and pass only real changes to user32.
- Ad SDK stub as the release default (`ad_sdk=0`): the dead ad network's SDK blocked the main thread on socket calls (120 ms frames).
- Profiler: samples every thread in the process (`profiler_extra_threads=2`, up to 16 threads, including DXVK's), names threads by description and start address, and for threads inside a Wine syscall shows the native (Linux side) instruction and stack as `file+offset`. Each report starts with a per thread summary table.
- The profiler is now off unless `profiler=1` is set, also when an older `dxhrfix.ini` lacks the key.
- Installers: take the game folder from the argument, the script folder or its parent; warn (and ask) on an unknown `DXHRDC.exe` instead of refusing; update an existing dxhrfix install in place; never overwrite `dxhrfix.ini`; never delete anything.
- Repository: MIT license, README, build and test without machine specific paths.

## 0.3.0

- Hitch profiler (`profiler=1`, diagnostics only). Hooks the engine's Present wrapper (0x54C9F0) to time frames on the render thread, samples the main, render, async create and file system threads, and writes a report for every frame longer than `profiler_hitch_ms` to `dxhrfix_hitch.log`: leaf functions, return addresses on the stack, top stacks, and `ReadFile` calls per thread that overlap the slow frame.
- `dxhrfix_syms.tsv` (generated by `tools/gen_syms.py`) gives the reports function names.

## 0.2.0

- Hook B, shader precreate (`precreate=1`, `pool_threads`, `precreate_max_per_sec`). When a shader library loads (0x54F000 / 0x54F080), every pixel shader nobody has asked for yet is created on a small DLL thread pool, so DXVK compiles it before the first draw needs it. Claims are atomic, a shader destroyed while listed is unlisted first (~PixelShader 0x54C910), two game helpers that cleared a shader pointer before requesting it are replaced (0x5535F0, 0x54C8D0), and device manager shutdown (0x54A440) stops the pool.
- Request claim under the device manager lock; pool threads at normal priority; duplicate listing skipped.

## 0.1.0

- Proxy `DFEngine.dll`: forwards the ad SDK to `DFEngine_orig.dll` or returns a stub, writes `dxhrfix.log`, byte checks every hook site.
- Hook A:
  - `awaitResource` (0x54C800): when the render or main thread needs a resource the single async worker has not created yet, it is taken out of the queue and created on the waiting thread instead of polling with `Sleep(1)`.
  - `cancelOrAwait` (0x54C850): a resource destroyed while queued is removed safely, and its destructor waits if it is being created right now.
  - Request (0x54C7D0) replaced whole: the queue slot is published in order under the engine's own lock. The stock code writes the slot outside the lock the worker reads under, a race that can lose a creation or run it twice.
  - `SetMaximumFrameLatency(1)` (0x54AB84) patched to `frame_latency` (default 2).
